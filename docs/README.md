## Описание проекта

**TODO Manager** – это плагин для VS Code, упрощающий и ускоряющий работу с комментариями в рабочем пространстве IDE.

Плагин предоставляет пользователю следующий функционал:

1. Подсветка комментариев в коде проекта.
   
2. Поддержка специального синтаксиса для разделения комментариев по типам и уровню приоритетности.

3. UI-компонент для боковой панели IDE, позволяющий быстро управлять комментариями из одного места.
  
Подробнее с возможностями плагина можно ознакомиться в секциях документации, располагающихся ниже.

## Поиск и анализ комментариев

При запуске VS Code плагин автоматически начинает свою работу. Используя VS Code API, плагин способен построчно анализировать каждый текстовый документ в текущем открытом проекте, чтобы находить комментарии в файлах и собирать информацию о них.

> [!NOTE]
> Плагин не будет собирать информацию о ВСЕХ комментариях. Область 
> ответственности плагина - комментарии определенных типов. Подробнее о типах
> можно прочитать [здесь](#типы-и-приоритеты-комментариев).

Плагин не анализирует ваш проект постоянно. Это процесс, который можно запустить двумя способами:

1. Команда `TODO Manager: scan workspace` в палитре команд VS Code.

2. Кнопка обновления в [UI-компоненте](#взаимодействие-с-комментариями).

Периодически эти команды необходимо выполнять, чтобы информация, которой владеет плагин, была синхронизирована с реальным состоянием проекта.

## Типы и приоритеты комментариев

Тип комментария - это его префикс, идущий перед основным содержанием. Данная система позволяет контролировать, какие комментарии плагин должен обработать, а какие - нет. Всего существует 4 типа комментариев:

| Тип     | Значение                                |
| ------- | --------------------------------------- |
| TODO    | Задача, которую необходимо выполнить    |
| BUG     | Баг в коде, причина которого неизвестна |
| FIX     | Решение для найденного бага             |
| NOTE    | Какая-то общая заметка о коде           |

Используйте типы разделяйте комментарии по категориям. Чтобы комментарий был найден плагином, придерживайтесь следующей структуры комментариев:

```
# (или любой другой символ начала комментария) TYPE: comment text
```

Данный комментарий будет обработан плагином:

```
# TODO: implement function add(a, b)
```

А эти комментарии - нет:

```
# WRONG-type: comment
# I don't have any type!
# wrong direction :TODO
```

Также вы можете устанавливать уровень приоритетности комментария. Для этого
перед его типом необходимо поставить `!`, `!!` или `!!!` (низший приоритет -> высший приоритет):

```
// !!! TODO: I'm super important
// !! FIX: Still important, but not that much
// ! NOTE: you can forget about me
```

Если приоритет не выставлен пользователем вручную, то он считается наименьшим. Если выставлен приоритет из более 3 символов, то считается, что у комментария такой же приоритет, как и при `!!!`.

Приоритет влияет на цвет [UI-элемента комментария](#визуализация), что позволяет быстро понимать, какая задача на данный момент более важна.

## Взаимодействие с комментариями

### UI-представление

Полученная после анализа проекта информация используется для построения древовидного UI-компонента, представляющего структуру комментариев в проекте. Данный компонент автоматически встраивается в боковую панель редактора после установки плагина и является главной точкой управления комментариями в проекте. Структура компонента выглядит следующим образом:

![пример-ui-элемента](./images/tree_view_example.png)

> [!WARNING]
> Обновление компонента не происходит автоматически: если вы хотите, чтобы 
> данные синхронизировались с текущим состоянием проекта, вам необходимо
> запустить команду для сканирования проекта.

Корневые элементы компонента - [типы комментариев](#типы-и-приоритеты-комментариев). В каждый корневой элемент вложены элементы файлов, а в каждый элемент файла вложены элементы комментариев данного типа, которые принадлежат этому файлу.

### Функционал UI

При клике на элемент комментария плагин откроет файл с выбранным комментарием и сфокурисует курсор на начале строки с этим комментарием. Также у каждого элемента комментария есть контекстное меню с тремя опциями, которое можно открыть, нажав ПКМ:

1. `Open comment` - производит аналогичные действия, что и при клике.

2. `Remove comment` - мягкое удаление комментария из UI-компонента. Физически комментарий останется в текстовом файле. Данная команда нужна в случае, если доступ к комментарию по какой-то причине невозможен и хранить его в компоненте нет смысла (например, был удален файл с этим комментарием).

3. `Delete comment` - жесткое удаление комментария и из UI-компонента, и из текстового файла, в котором он находится.

> [!IMPORTANT]
> Если после удаления комментария оказывается, что в файле больше нет комментариев данного типа, то из компонента удалится и элемент комментария, и элемент файла. Если это приводит к тому, что корневой элемент становится пустым, то корневой элемент также удаляется.

При нажатии на кнопку "Перезагрузка" происходит повторный анализ проекта для синхронизации плагина с его текущим состоянием.

### Визуализация

Каждый элемент комментария помечен цветом: зеленым, желтым и красным. Цвет комментария соответствует его [уровню приоритетности](#типы-и-приоритеты-комментариев). Зеленый - низший приоритет, красный - высший.

Также у корневых элементов и у элементов файлов есть свои иконки. Если вам не нравятся иконки для корневых элементов, вы можете отключить их в [настройках плагина](#настройки-плагина).

## Подсветка комментариев

В отличие от обновления UI-компонента, подсветка комментариев происходит в режиме реального времени. Каждый [тип комментария](#типы-и-приоритеты-комментариев) имеет свою собственную подсветку:

![типы-комментариев](./images/types_example.png)

Если вам не нравится подсветка комментариев, вы можете отключить её в [настройках плагина](#настройки-плагина).

## Настройки плагина

Для плагина существует два настраиваемых пункта:

1. `Highlight comments` - вкл / выкл [подсветки комментариев](#подсветка-комментариев) в коде.

2. `Show group icons` - вкл / выкл [иконки для корневых UI-элементов](#визуализация).
